# 第二轮：在 B 格式上试三种回放算法，并补"每次现做"的基线（设计与过程记录）

日期：2026-11-13　基础：第一轮结论（`docs/test/2026-11-12-procedure-format-experiment.md`，选 B）　代码：`computer-use`（`5e7ef2b`）原样，算法全部做在实验插件里（`.host/lab2/`，不进仓库）

## 这一轮主要测什么

第一轮定了"存成什么形式"（B：JSON + 页面内脚本）。但同一轮也看到，坏掉的主要原因和形式无关：

| 第一轮的问题 | 程度 |
|---|---|
| 页面换了 class 名（v2），工具不修就坏 | 六成多的运行 |
| 坏了却不报错，说"完成"或返回空 | 90–110 次回放 |
| 修好新页面，旧页面又坏了 | 修好的里约一半 |
| 发送后立刻检查，页面还没跳转就判失败 | 1 次运行全坏 |

这一轮回答三个问题：

1. **三种不调模型的回放算法，各自能把这些问题减少多少？**
   - **F 指纹自愈**：工具每次跑成功，记下它用到的元素长什么样（标签、属性名、`data-*`、上下层结构，不记 class）。下次 CSS 选择器找不到东西时，按指纹找最像的元素接着跑。针对"换了 class 名"。
   - **K 结果契约**：提取到 0 条、某个字段每一条都是空、页面脚本返回空，都按失败报出来，不再说"完成"；检查页面文字时最多等 3 秒。针对"坏了不报错"和"发送后立刻检查"。
   - **V 旧版兜底**：最新版没跑通、而且还没有任何向外的动作时，按从新到旧试她留下的旧版本（库里本来就留着 `.v<n>.json`）。针对"修好新页面、旧页面又坏了"（灰度、A/B 测试时新旧页面同时存在）。
2. **三种一起用（FKV）时，她修工具的情况会不会变好？** K 让她拿到真实的失败报告，而不是第一轮实验判定器替她写的"期望结果包含……"；F 和 V 让一部分改版根本不需要修。
3. **存工具到底划不划算？** 第一轮没有和"不存工具、每次让她现做"比过。近期研究（EMNLP 2026）发现，很多"存技能"的收益在同等预算的基线面前会消失。这一轮加一组 N：同样的任务，每个页面版本让她现做一次，量成功率和单次花费，和"学一次 + 回放 + 偶尔修"的总花费比较。

不测的：存储形式（第一轮已定）、桌面直控、Mac、真实 B 站、她的性格。

## 和第一轮一样的

模型 `deepseek-flash`、真 DSH 容器、无人设的新世界、五个任务的说法、学习提示、修复提示的模板、站点的数据和 v1/v2。

## 和第一轮不同的

- **v3 叠在 v2 上**：哈希 class + 外包 div，再加"更多"下拉、弹窗、分页。第一轮的 v3 是在 v1 上改的，按 class 写的工具到 v3 反而能用，这次堵上。
- **弹窗随机出现**：每次加载页面，按（种子, 第几次加载）决定弹不弹，大约一半；第一轮偶数种子每次都弹。
- **回放每组 5 次**（第一轮 10 次）；"能用" = 5 次至少 4 次成功。第一轮的回放几乎全是 0/10 或 10/10，5 次够分辨。
- **同一个学会的工具，用不同算法分别回放**：学习只做一次（B 原样），之后同一份工具在 base / F / K / FK 四种配置下各自回放 v1、v2、v3。算法之间的差别不受"她这次学得好不好"的影响。
- **修复分两支**：从同一个学会的工具复制两份。
  - base 支：照第一轮的做法，静默失败时用判定器的文字。
  - FKV 支：失败报告来自 FKV 自己的回放；她修的时候，`my_` 工具也走 FKV。
  - 两支修完都回放 v3、v1、v2 各 5 次。

## 每次运行

工具组，5 个任务 × 5 次 = 25 次运行：

1. 在 v1 上学（模型）。
2. base、F、K、FK 四种配置，各回放 v1×5 → v2×5 → v3×5。F 的指纹在 v1 跑成功时记下，各配置分开存。
3. base 支：base 的 v3 没全过就修（模型），修后用 base 回放 v3、v1、v2 各 5 次。
4. FKV 支：FKV 的 v3 没全过就修（模型，`my_` 走 FKV），修后用 FKV 回放 v3、v1、v2 各 5 次。

现做组 N，5 个任务 × 5 次：

- 每次分别在 v1、v2、v3 上，用新世界、只给 `page_*`，让她把这件事做一遍，用一两句话汇报。
- 读类任务看她最后的回答；发送类任务看站点日志，要求恰好一条，对象和内容都对。

## 判定规则（先写下）

- **算法有没有用**：同一批工具，比较 F、K、FK 和 base 的"v2 能用""v3 不修能用""静默失败数"。和 base 的差距大于 5 个运行，算有效果；小于等于 2 个，算没效果；中间的如实写"不确定"。
- **FKV 修复**：比较两支的"修好率""修好后 v1、v2 仍能用"和修复花费。判法同上。
- **划不划算**：按"每个版本各用 10 次"算总花费和总成功次数。
  - 工具路线：学习 + 修复的花费，加上回放的成功率。
  - N：3 个版本 × 10 次 × 单次花费，加上 N 的成功率。
  - 工具路线在成功次数不少于 N 的前提下，总花费更低，才算划算。
- **安全**：任何组出现误发、重发、发错人，单独列出并分析能否在算法层堵住。F 可能把点击落到"最像但不对"的元素上，向外的步骤尤其要核对。

## 已知的局限（先写下）

- 指纹只能救 CSS 锚点和提取字段，救不了她写在页面脚本里的 class 选择器。
- K 不允许"本来就可以为空"的提取；这五个任务都不会为空，真用时要加一个"可以为空"的声明。
- V 只在没有向外动作时兜底，发送类工具第一步就向外的话救不了。
- N 的每一次都是新世界，没有"上一次做过"的记忆；这也是存工具想解决的。
- 学习阶段她不知道有 F/K/V，K 的规则只在修复时通过失败报告让她知道。

### 2026-11-13 续跑（用户授权清理内存）

- 用户的要求：继续在容器里跑；内存不够就清理，只保留桌面 DSH 会话和 Claude Code 自己的进程。
- 主实验改为独立进程（`Start-Process` 起的 `cmd /c node run2.mjs --concurrency 2 --resume`），不再挂在 Claude Code 的后台任务下，Claude Code 在内存紧张时停后台任务的机制管不到它。
- 内存守护（独立进程）：每 30 秒查一次。低于 2500 MB 清 Docker 虚拟机的页缓存；清完仍低于 1500 MB，就关掉几个非必要的桌面程序。每次动作都记进日志；主实验写出 ALL DONE 后自己退出。
- 续跑时跳过已完成的 8 次，剩 42 次。

### 2026-11-13 一次脚本崩溃

- 工具组任务 2 r4：复制修复分支的世界时，Chromium 的缓存文件在复制中途消失（`ENOENT …/Cache/Cache_Data`），容器脚本崩溃。回放结果原先只在最后才写盘，所以这次的回放全丢了。
- 修法：复制时跳过浏览器缓存目录；每跑完一组回放就写盘；流程出错时记下错误再退出。镜像已重建，之后的运行都用新镜像。
